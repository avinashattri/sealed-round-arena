Commit-Reveal Sealing & Verification Protocol

Demonstration of Phase 1 (Commit), Phase 2 (Seal with Curve25519 SealedBox), and Phase 5 (Reveal & Validate).

1. Commit Phase (Phase 1)

Red commits SHA-256 hash of plaintext attacks. Attacks are stored in plain memory on the client.

SHA256(challenge_id + input + salt) --> Recorded in commitments.json --> Pinned to Audit Log

2. Sealing Phase (Phase 2)

Curve25519 SealedBox encrypts challenge payload using Referee Public Key. Client cannot decrypt it.

SealedBox.seal(payload, referee_pubkey) --> Stored on disk under evidence/sealed/ --> Mode A execution begins

3. Reveal & Integrity (Phase 5)

Red reveals plaintext attacks. Controller recalculates SHA-256 and checks against Phase 1 commitment.

if sha256(revealed) != commitment: COMMITMENT MISMATCH: ['ch-0003'] Status: REJECTED & FLAGGED
